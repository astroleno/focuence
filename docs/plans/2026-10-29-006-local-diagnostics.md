# 本机运行日志与效果分析

基线：`c2c9140`。用户已确认实施上一轮讨论的本机结构化日志与分析；沿用 `main`，主线程执行，不新增 agent、分支、worktree 或公网部署。沿用验收后 commit / push 的交付授权。

## 目标与存储设计

- 记录采集状态与忽略原因、本机模型/AI 的耗时和用量、候选展示/打开/采用/保存、分组预览/应用/撤销，支持排错和观察主线使用情况。
- 新增 `diagnostics` 模块与独立 IndexedDB `focuence-diagnostics-v1`，不升级或改写任务数据库，不进入任务备份、向量索引、云服务或浏览器历史。
- 默认启用；固定保留 7 天，最多 5,000 条。状态变化记录，重复采集状态最多每 5 分钟采样一次，避免每次刷新写一条。最近列表最多返回 50 条，完整导出也受总量限制。
- 严格白名单字段：事件类型、时间、随机操作编号、来源/协议类别、状态/错误码、数量、耗时、token 用量。禁止标题、网址、任务名/目标、输入/补全文本、密钥、响应正文、任意报错消息与堆栈。仅在内存核对候选与保存文本，日志只保存匹配后的事实。
- 关闭立即停止新记录；清空或关闭使进行中的旧请求失去日志写入资格，重新开启后也不能补回。日志故障不影响保存任务、访问记录、分组或 API 返回；界面明确显示记录不可用或丢弃数量。
- 清除历史同时清除运行日志，清除全部恢复日志默认配置；单独清空日志不改变浏览记录、任务或 AI 配置。浏览记录暂停时，不记候选/任务/分组的行为事件；可保留无内容的采集暂停状态与服务诊断。界面和隐私说明明确两个开关的边界。

## 模块与接口

- `src/diagnostics.js`：字段清洗、用量口径与纯统计。`src/diagnostics-service.js`：采集去重、有界待写队列、写入隔离与请求作用域。`src/diagnostics-store.js`：保留清理、独立持久化与设置。
- `background.js`：统一接入真实采集状态、本机语义计算、分组与断点保存结果。日志接口独立于主数据库启动，便于主流程故障时读取诊断。
- `src/ai-provider.js`：保持生成返回值不变，旁路记录实际请求耗时、结果、协议和 usage；缺少 usage 标为未知。Anthropic 的缓存读/写与普通输入统一统计并保留缓存子项，OpenAI 的缓存输入作为输入子集，不重复累加。
- `src/prediction.js`：每次返回带短期随机追踪编号；后端验证展示/采用反馈、候选索引、有效期与版本，操作去重。页面打开只在真实打开成功后记；补全采用仅填草稿，保存后才记保存事件。
- `src/prediction-ui.js`、`src/task-memory-ui.js`：仅对实际可见结果确认展示；输入变化与关闭重开清除补全来源；保存时携带可核对的候选引用，手改后的文字不算原样保存候选。
- `GET_DIAGNOSTICS {range:'24h'|'7d'}` 返回设置、健康状态、统计与最近记录；`SET_DIAGNOSTICS {enabled}`、`CLEAR_DIAGNOSTICS`、`EXPORT_DIAGNOSTICS`；候选反馈使用后端签发的编号，不接受任意事件文本。
- “数据与设置 → 运行与记录”提供开关、24 小时/7 天范围、刷新、汇总、最近记录和独立导出/清空。沿用现有组件与样式；示例页只展示示例空状态，不操作真实日志。

## 分析口径

- 展示次数来自界面可见确认，不用生成成功代替展示。页面打开/任务查看、补全采用、原样保存均按不同操作阶段统计。
- 分母只计同一范围内实际展示的操作，跨期或缺少展示的后续行为另计，不产生超过 100% 的采用率。下一步与查找补全分别统计，避免把查找补全算成待保存断点。
- AI 未启用属于本机模式；AI 模式中的服务失败回退单列。取消/过期与故障分开。报告耗时中位数/95 分位数和已报告用量的覆盖率，不把未知 token 当成 0。
- 显示真实保留范围、样本数和容量裁剪提示。行为采用率不称为准确率，也不据此宣称节省时间或提升专注。

## 验收与交付

1. 单元测试验证字段白名单、环形保留、关闭/清空后晚回包、失败隔离、token 口径、去重、分母/分位数与未知用量。
2. 真实 MV3 验证日志持久化与独立导出/清空、采集原因、预测展示/打开、补全采用后保存及手改/放弃边界、分组应用/撤销；测试只用合成页面和数据。
3. 运行原有查找连续性、分组与预测回归；320/360/1440 px 视觉/溢出检查。验证生成返回及主流程不依赖日志存储成功，记录实际写入与查询开销。
4. 全量单元测试、扩展/网站构建；Ego 加载新版本，检查真实日志入口与记录状态。保留正式验收文档，清理本轮测试资料、过程截图与临时服务。
5. 验收后 commit / push。Ego 既有跨页前台采集限制仍需如实保留，不为日志验收注入访问或放宽前台定义。

## 执行结果（2026-10-30）

2.7.0 已实现上述模块、入口与清理边界。189 项单元测试、15 项新增真实 MV3 验收、17 项连续性/分组回归、6 项真实 BGE/预测/地图回归均通过；扩展及网站构建通过，未部署公网。Ego 已通过扩展管理页重新加载真实 2.7.0，运行日志开启、存储可用、丢弃 0 条；未开启 AI 或安装密钥。

在隔离浏览器内以 5,000 条保留记录测试，20 次追加写入中位数 0.5 ms、95 分位约 0.6 ms，读取全部约 20.6 ms。该结果仅为本机验收样本。Ego 仍会报告多个窗口同时聚焦，旧的跨页地图验收限制不在本轮解除。完整结果见 [2.7 验收](../reviews/v2.7/README.md)。

## 优先处理的已确认问题

### R1 · P1 · 日常观察与打开结果会清空检索作业

合并 kimi F-001 与 DeepSeek CORE-01。根因是共享的全量失效机制：标签事件调用 `workspace.invalidate()`；活动片段的例行 checkpoint 也调用它；该函数推进代次并把全部作业设为 stale、清空结果，而不区分检索来源是否真正改变。

位置：[background.js:59](../../../../background.js#L59)、[background.js:554](../../../../background.js#L554)、[src/workspace.js:83](../../../../src/workspace.js#L83)。

本轮在 Chrome 156 的真实 MV3 中确认两个触发：

- 关闭记录和模型，只查已保存任务。打开第一条结果后，原作业变为 stale；继续取结果、看来源、打开第二条均返回 `STALE_SUGGESTION`。
- 开启记录，前台保持在同一合成网页，查已保存任务。一次 `GET_STATE` 就把已完成作业从 done/2 条结果变为 stale/0 条；没有修改所检索的任务资料。

这会打断“找回 → 打开 → 回来继续找”的核心循环，也支持对关联/语义分析轮询失效的担忧。但本轮没有运行真实模型长批次，不能据此断言所有语义操作必然失败，原文中的绝对化表述不采纳。

修复应区分观察 checkpoint、来源变化及作用范围，保留仍有效的已完成结果，执行动作前核验目标身份；不能直接照搬“移除全部失效”的建议而放松导航、删除或权限边界。需补覆盖后台实际事件接线的回归。

### R2 · P2 · 返回提示会混用两个窗口的上下文

确认 DeepSeek CORE-02 的返回提示部分。两个窗口均已选择同一任务时，`view(windowId)` 取请求窗口的当前意图，却把全局前台窗口的 `activity.context` 交给 `returnPrompt`。提示生成时未核对请求窗口；反馈时才核对，因此可能先显示外窗提示，再拒绝所有操作。

位置：[src/workspace.js:244](../../../../src/workspace.js#L244)、[src/focus-support.js:7](../../../../src/focus-support.js#L7)、[src/workspace.js:407](../../../../src/workspace.js#L407)。

真实协调器与活动预览函数、内存存储夹具复现：请求窗口 1，前台窗口 2，返回提示的窗口也是 2；窗口 1 的展示确认返回 `STALE_CONTEXT`。这是协调器边界复现，未做两窗口可见侧栏的原生点击实验。“继续线索也必然错误”的扩展指控未单独确认。

修复方向：生成提示与处理反馈使用同一请求窗口契约，不匹配时不生成该窗口的提示。

### R3 · P2 · 长时间偏离后的提示一出现就可能失效

主线程补充发现。提示展示读取整个保留期，反馈只读取近一小时结束的片段；ID 又包含连续片段序列的最早 segment ID。用户在同一任务意图下连续访问其他已确认页面超过一小时、此前未展示过提示时，两次计算可以得到不同 ID。

位置：[src/workspace.js:249](../../../../src/workspace.js#L249)、[src/workspace.js:409](../../../../src/workspace.js#L409)、[src/focus-support.js:29](../../../../src/focus-support.js#L29)。

六段各 20 分钟、两个页面的合成记录中，展示累计 120 分钟，反馈集合累计 80 分钟（结束时间索引也包含跨截止时间的片段）；ID 不同。真实协调器的展示确认直接返回 `STALE_CONTEXT`。没有等待两小时做真实浏览实验。

修复方向：统一展示/反馈的评估范围和连续段锚点，使有效提示的身份保持稳定；不能用每次随机生成 ID 的方式处理，这会破坏展示确认的幂等性。

### R4 · P2 · 已排除站点仍进入自动继续候选

确认 DeepSeek AUX-01。`computeAnalytics/buildSuggestions` 读取旧片段、页面索引与保存任务页，只有 URL 合法性过滤，没有接入站点排除规则；界面也仅检查 HTTP(S)。

位置：[src/analytics.js:181](../../../../src/analytics.js#L181)、[background.js:304](../../../../background.js#L304)、[app/app.js:426](../../../../app/app.js#L426)。

隔离 MV3 中先保存合成资料，再排除 `excluded.fixture.test`；下一次 `GET_STATE.suggestions` 仍返回该网址，方法为 task。没有打开外部网站或使用个人历史。

修复方向：自动候选应用排除规则。已有保存资料的可见性与显式恢复继续遵守原契约，不应借此删除用户资料。

## 产品取向

后续优先修复“看到注意力与当前目标 → 找回线索 → 回来继续”的连续性。地图和聚焦是核心，资料库、浏览器历史与备份应帮助这条路径。DeepSeek 的当前工作首屏、侧栏跨视图返回入口、回顾显示未知/暂离覆盖、固定当前任务等建议值得进入后续设计；不是本轮已批准改动，也不能据此推断专注分数或心理状态。地图继续保留访问先后、真实次数和证据口径，不把前台时长当实际注意力。

# Focuence 2.7.1 性能与任务接续评审

日期为 2026 年 11 月 25 日。评审范围为扩展工作台、原生侧栏和工具栏弹窗，使用仓库已有设计约定、隔离 Chrome 与合成资料。

## 评审结论

| 优先级 | 发现 | 本轮处理 |
| --- | --- | --- |
| 高 | 检索界面每批固定等待 150 ms。1,100 份文档共有 46 批，仅批间等待就增加约 6.75 秒。每批还会重新绘制整个界面，替换正在输入的查找框和已取得焦点的结果。 | 按批次让出界面线程并局部更新。持续提供结果、进度、停止和来源核对。 |
| 高 | 原有快照固定检索文档，仍从实时列表取来源。同一 URL 和标题的两个标签从 1、2 换成 2、3 时，文档签名不变，原来的来源却被替换，分页也可能漂移。 | 搜索结果和来源均按本次查找建立快照，打开现有标签时继续核对当前 URL。 |
| 中 | 限定查找范围后，后台仍读取不在范围内的浏览记录和窗口。合并同一个 URL 的标题又使结果难以指出具体命中了哪次记录。 | 按有效来源读取，并在结果和来源明细中指出参与匹配的标题或文字字段。 |
| 高 | 排除的任务断点地址仍可命中域名筛选并出现在来源明细。已保存的框架资料也可能带出排除的父页面地址。 | 筛选和来源明细使用同一站点排除规则，保留任务文字和已保存的允许资料。 |
| 中 | 按访问时任务筛选时，跳过资料库会遗漏由资料库提供的当前任务归属。 | 分别核对观察时的任务和当前关联，限定来源读取时保留必要的归属查找。 |
| 中 | 聚焦页的窗口操作和预测说明占据多行。窄侧栏的当前任务与任务卡重复展示继续操作，未选当前任务时聚焦卡缺少直接入口。 | 当前目标、确认断点和继续动作放在首屏。辅助操作按需展开，保留任务清单与键盘访问。 |

BGE 模型、每批 24 份文档、入选来源的完整检索范围和任务恢复规则沿用 2.7.0。时间、站点和任务筛选先于推理。判定命中质量时分别看关键词、语义补足和来源证据。

## 同机对照

在同一台 Mac 的隔离 Chrome for Testing 156.0.8078.47 内，分别对 2.7.0 包和 2.7.1 候选源码运行真实检索表单。每版预置同样的 1,000 个保存页面和 100 个合成任务，提交同一条已知标题查询四次。冷启动各测一次，热查询各测三次。

| 指标 | 2.7.0 | 2.7.1 |
| --- | ---: | ---: |
| 首条关键词结果 | 34–91 毫秒 | 58–122 毫秒 |
| 冷查完整分析 | 21.98 秒 | 19.85 秒 |
| 热查完整分析中位数 | 10.23 秒 | 6.46 秒 |
| 46 批中批间请求等待合计 | 约 6.85 秒 | 30–39 毫秒 |
| 搜索时保留原输入框 | 0/4 | 4/4 |

2.7.1 热查样本为 6.46、8.72、5.75 秒，中位数用时缩短约 37%。首条结果用时略增，来源校验仍需读取有资格入选的记录。分析期间可继续输入、查看已经出现的结果和核对来源。单机、小样本数据用于对照交互和完整分析耗时。

## 独立验收

- 196 项单测通过。覆盖原始来源的身份、顺序及时间、同标题新记录、分页、旧结果打开、站点排除、观察归属与当前关联。
- 真实 BGE 完整分析 1,100 份文档。8 份合成材料中的 3 条查询均把目标排在第 1，两个目标经语义补足进入首位，无关查询返回 0 条。结果卡和来源详情能指明命中的是自己的笔记。该小样本覆盖典型用法，整体召回率和误检率仍待用真实检索集量化。
- 原生浏览器测试确认输入、中文组字、选区和滚动在批次更新中保留，停止后迟到的批次不会覆盖已有结果。工作台、侧栏和弹窗共通过 12 个聚焦布局状态。320 像素宽侧栏的继续按钮底边从 484 移到 327 像素。任务接续、预测相关性与本机诊断也通过原生验证。

主线程另用原生 Chrome 历史 API 写入 10,000 条合成访问，逐条核对导入的访问 ID。删去一条后可检索其余 9,999 条，最后一页返回 49 条。后台重启后仍可核对原始访问 ID，撤回历史权限后旧查询的来源访问失效。

2.7.1 ZIP 在隔离配置中以公开 1.0.0 的扩展 ID 替换运行，原生升级测试通过 6 项检查，包括旧存储键保留、AI 默认关闭及随包模型的语义检索。该验收使用开发者模式加载。同一 ID 的正式商店更新仍需由发布者验证。[升级验收说明](../../../CHROME_STORE_SUBMISSION.md)

旧版原生性能样本和验收范围可查阅 [2.4 历史与性能验收](../v2.4/README.md) 与 [2.7 本机日志验收](../v2.7/README.md)。

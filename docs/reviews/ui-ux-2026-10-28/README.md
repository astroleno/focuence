# Focuence 前端 UI/UX 与概念一致性评审

2026-10-28 · 源码 `bbdac61` · 扩展 2.5.0 · 官网发布 `focuence-site-7e1b2add0bb6`

**后续修复：** 用户已授权并实施本报告全部 5 项 P2、4 项 P3，逐项结果与验证边界见 [修复验收](fixes/README.md)。下文保留修复前的独立评审基准，不将旧截图当作当前界面。

官网已经把“注意力地图 → 当前聚焦 → 断点继续”讲清楚，侧栏选定当前任务后的首屏也符合这条主线。主要落差在默认入口、任务列表的动作主次，以及地图证据和编辑流程的连续性。现有视觉体系和数据模型可以继续使用，优先改善用户能否顺着同一件事继续操作。

本次完成了用户要求的两个独立子 agent 评审：[Lama 原报告](lama-review.md)、[Emil 原报告](emil-review.md)。两人分别读取对应 Skill 与底层规范，独立阅读源码和同一批浏览器证据，未读取对方报告。主线程在两份报告完成后复核、合并并排序。原报告保留各自结论，下面的优先级是主线程最终判断。

## 优先处理的问题

确认 5 项 P2、4 项 P3；其中 3 项 P2 已通过实际前端交互复现。入口与层级的用户理解后果属于设计判断，尚未通过真实用户研究测量。没有在本轮 UI 范围内确认 P1，不代表产品全量验收通过，也不代表历史后台问题已修复。

## 应保留的设计与概念

| 概念 | 应贯穿各入口的含义 | 本次判断 |
| --- | --- | --- |
| 注意力地图 / 主题 | 描述观察到的浏览内容与访问先后；前台记录不等于实际注意力或完成度。 | 定义与证据口径正确；完整图的双列访问角色与侧栏局部图可继续使用。 |
| 当前聚焦 / 当前任务 | 用户决定眼前要推进的事，通过当前窗口绑定一个任务表达。 | 对象正确，默认入口与叫法应衔接。不能直接把所有保存动作改为开始聚焦。 |
| 确认断点 | 用户写下的进展、卡点、下一步和继续页面；系统访问记录只是线索。 | [官网断点示例](screenshots/website-checkpoint-desktop.png) 的简化符合演示用途；真实端边界清楚，应补编辑保护与连续操作。 |
| 相关判断 / 保存页面 | 前者用于识别相关，后者用于恢复清单；二者分别管理。 | 已有解释与不同按钮，继续保留。 |
| 继续一页 / 恢复保存页 | 单页接续与批量恢复是不同意图。 | 两种能力均需保留，按当前意图调整主次。 |
| 暂停当前任务 / 暂停记录 / 任务状态 | 分别影响窗口绑定、记录开关和任务生命周期。 | 实现分开合理，通过短文案解释作用范围。 |

侧栏选定当前任务后，[目标、“继续一页”和“留断点”已在首屏](screenshots/panel-current-task-first-viewport.png)，关联内容默认收起，是可复用的良好层级。

[侧栏局部地图](screenshots/panel-map-360.png) 展开到 [完整地图](screenshots/panel-map-expanded-workbench.png) 时，本轮实测保留 `range=today`、选中主题“声音与硬件”、`from=视觉创作`、`to=声音与硬件`，两端页面和 09:45 的例证也保留。它与 R2 是不同的交接，不能泛称所有地图导航都丢上下文。

系统字体、中性色表面、蓝色选择与深色主要按钮构成一致的工作工具风格。当前没有需要更换视觉语言或加入大量位移动画的证据。

## 覆盖范围、排除项与限制

- **覆盖：** 公网官网桌面和 390×844 窄视口；弹窗等效 400×600；侧栏等效 320/360×760；完整工作台 1440×950；任务空态与选中态、创建目标表单、地图和关系详情、路径、查找结果、共享设置布局。设置来源见 [设置截图](screenshots/workbench-settings.png)，入口 `options/options.js` 跳转以源码确认。
- **两份独立审阅共享证据但独立判断。** 浏览器由主线程统一操作，避免相互干扰。两个 reviewer 没有各自运行一套原生扩展验收；不能把两份意见当成两次独立实验。
- **数据与时钟：** 扩展界面采用项目原有 `?demo=1` 合成数据。地图合成片段从当天 08:40 生成，早于该时刻采集会看不到这些片段；相关地图初始化仅在隔离页面将 `Date` 固定为 2026-10-28 13:00 +08:00。未改系统时钟、产品源码或私人扩展资料。最早地图的零关系不计缺陷。
- **明确排除：** 390×844 官网保存目标和断点后，预览与状态文字均可见，不能列为“保存没反馈”，参见 [目标保存](screenshots/website-focus-mobile-after-save.png)、[断点保存](screenshots/website-checkpoint-mobile-after-save.png)。demo 新建目标后未在列表显示新增任务仅记为适配器证据限制，不据此新增真实扩展缺陷。[零页面目标表单](screenshots/popup-new-task-400.png) 证明已有该入口，不把“先保存、再设当前”的显式状态分离自动判为 bug。
- **未执行：** 原生工具栏弹出层和浏览器侧栏宿主的生命周期、原生标签页复用/系统焦点、浏览器历史授权、真实模型推理、真实备份恢复/清除、屏幕阅读器与触摸真机、用户研究及长列表压力验收。demo 的设置占位不能作为这些流程成功或缺失的证据。
- **本轮范围：** 仅 UI/UX 与概念一致性审阅、证据复核和文档交付。历史检索/返回提示等后台 findings 未复测，不据此关闭；没有修复、部署或自动提交推送。

建议后续先完成 R1–R3，再确认 R4–R5 的入口与任务卡设计，最后一起处理 R6–R9 的短文案与公共样式。以上是待实施建议；本次没有把建议写成已经通过的产品改动。

完整方法与入口映射见 [CONTEXT.md](CONTEXT.md)。Lama 与 Emil 的详细场景、源码行号和各自验收条件分别保留在原报告中。

## 需修复的问题

### L-R1 · P2：新建/编辑任务和手动材料编辑仍会在退出时丢失输入

**触发：** 完整工作台点击“新建任务”，填写名称、目标和备注，按 Esc，再次新建。新建表单三个字段均恢复为空。编辑已有任务更改目标和备注后关闭，再次编辑，也只剩旧值。资料库手动“粘贴摘录”填写标题、来源、原文和笔记，Esc 退出再打开，四项输入全部为空。

**用户后果：** 同一产品的“留断点”会提示继续编辑/放弃，写目标、任务备注和研究笔记却直接丢弃。用户无法建立一致的退出预期；这些恰是帮助恢复思路的人工内容。这里是普通页面内显式退出，不能归因于原生工具栏弹窗被浏览器销毁。

**证据：** `workbench-task-new-draft` → `workbench-task-new-escape` → `workbench-task-new-reopen` 的 `fields`；`workbench-task-edit-draft` → `workbench-task-edit-reopen`；`library-draft-before-escape` → `library-draft-after-escape` → `library-draft-reopen`。截图：[任务草稿](screenshots/workbench-task-new-draft.png)、[材料草稿](screenshots/library-draft-before-escape.png)、[材料重开后为空](screenshots/library-draft-reopen.png)。

**定位：** [app/app.js](../../../../app/app.js) L787–790、L822–845、L1180–1184：任务表单没有 dirty 退出处理，Esc 仅在 busy 或另有取消回调时被拦截。[src/library-ui.js](../../../../src/library-ui.js) L17–20、L31–32：空闲时直接关闭，重新进入 editor 即重建 form。对照 [src/task-memory-ui.js](../../../../src/task-memory-ui.js) L81–99，断点已经有独立的改动保护。

**方向与验收：** 将“有改动后退出需明确继续编辑/放弃”的交互覆盖任务与手动材料编辑。保存失败、冲突核对和改动保护使用同一份草稿；未修改时可以直接关闭。逐项复测 Esc、关闭和返回，确认选择继续编辑保留文字、光标及选择项，明确放弃才清空。无需由本问题推导出跨浏览器重启的永久草稿功能。

### L-R2 · P2：状态筛选下的新建目标保存成功，却无法进入聚焦流程

**触发：** 当前聚焦页将任务状态筛选设为“已完成”，示例没有该状态任务。空状态仍显示“先给眼前的事一个目标”和“新建任务”。从这里新建并保存一个目标后，仍是“0 个任务”和相同的新建引导；切换“全部任务”才看到刚保存的任务。

**用户后果：** 数据已经保存，但界面引导用户重复新建，不能接着“设为当前聚焦”。左侧总数变为 4、中间仍显示 0，界面又未解释筛选造成的差异。这是“先写目标 → 选择当前聚焦”主线中的可见性断点。

**证据：** `workbench-completed-filter-empty` → `workbench-filter-create-result` → `workbench-filter-create-task-exists`；[保存后的空状态](screenshots/workbench-filter-create-result.png)。观察中保存反馈出现，切回全部后“复审筛选后新任务”存在，确认不是保存失败。

**定位：** [app/app.js](../../../../app/app.js) L377–389：空状态仅区分文字查询与否，没有区分状态筛选。L880–882：保存后仅刷新、关闭和提示。[src/task-memory-ui.js](../../../../src/task-memory-ui.js) L404–406 保存状态筛选，新的进行中任务继续被过滤。

**方向与验收：** 筛选无匹配应明确“没有已完成任务”等，并提供查看全部入口。创建成功后直接呈现新任务及“设为当前聚焦”，或给出可操作的“查看刚保存的任务”反馈；不能只留下成功提示。复测已完成/等待/归档筛选和文字查询组合，不把保存误当自动开始聚焦。

### L-R3 · P2：用键盘选择完整地图关系后，焦点回到内容起点

**触发：** 在完整地图中用 Tab 定位 SVG 关系，按 Enter 选择。关系确实选中，但焦点由该 `g[role=button]` 变成 `MAIN#main`；下一次 Tab 到达顶部时间范围 `#map-range`，需要重新走过地图前面的控件。

**用户后果：** 键盘用户每次核对一条关系都会丢失位置，难以连续比较关系及访问例证。先前修复的“从路径返回所选关系”是另一条路径；它通过不能证明普通选择也保住焦点。

**证据：** `map-edge-keyboard-before` → `map-edge-keyboard-after-enter` → `map-edge-keyboard-next-tab` 的 active 记录；[选择后截图](screenshots/map-edge-keyboard-after-enter.png)。另有 `map-path-return-focus` 确认路径返回能落到原关系，故不将两种情形混为一项已修复问题。

**定位：** [app/app.js](../../../../app/app.js) L629–632：关系线在下一帧生成。L767–775：render 的同步焦点恢复运行时，新 SVG 关系尚未生成，回退到 main。L1091 选择关系调用完整 render；L625–627 仅保护同一 wire 的 ResizeObserver 重画，没有覆盖本次完整重建。

**方向与验收：** 在关系真正挂载后恢复稳定关系 ID，或让关系节点在选择更新时保持身份。Enter、Space、鼠标选择、地图范围变更和 ResizeObserver 重画分别验证。键盘完成一次关系选择后，焦点应仍在该关系或明确移动到对应例证，不能静默回到时间筛选。

### L-R4 · P2：视图切换沿用页面滚动，当前聚焦区会完全不可见

**触发：** 完整工作台任务页滚到较下方，通过固定导航切到地图，再切回“当前聚焦”。本次真实页面滚动为 `1203px → 370px → 370px`。切回后当前聚焦块的顶部为 `-161.60px`、底部为 `-42.91px`，整个块处于视口上方。

**用户后果：** 用户明确点击“当前聚焦”，却落在普通任务列表中，眼前的任务、目标和暂停/继续区没有出现；地图也从中段打开，标题和范围都在屏幕外。这削弱了已经统一的入口和层级。

**证据：** `navigation-window-deep-tasks-before` → `navigation-window-deep-to-map` → `navigation-window-return-focus` 的 geometry；[进入地图的落点](screenshots/navigation-window-deep-to-map.png)、[返回当前聚焦的落点](screenshots/navigation-window-return-focus.png)。最初 `navigation-deep-*` 只改 `main.scrollTop` 而实际为 0，没有形成深滚动，**不采用**那组记录证明此项。

侧栏对照 `panel-deep-focus-before-navigation` → `panel-deep-return-focus` 中，main 从 1016.5px 变为 10px，当前块 top=213.5px、bottom=466.7px，仍然可见。**本项只确认完整页失败，不扩成三端共同失败。**

**定位：** [app/app.js](../../../../app/app.js) L779–784 只换视图和刷新，没有处理视图落点。[app/styles.css](../../../../app/styles.css) L8–9、L25、L35 的完整页使用文档滚动；侧栏 L349 才是 main 内部滚动，因此不能只修完整页的 `main.scrollTop`。

**方向与验收：** 给新视图明确落点；显式“回到当前聚焦”应显示当前块。若希望各视图记住阅读位置，应按视图保存与恢复，并保证重选聚焦入口可以回到聚焦区，避免将 A 视图坐标直接带到 B 视图。长任务、长地图和 320px 侧栏分别复测真实滚动容器。

### L-R5 · P3：扩展地图的可见时长没有解释前台分摊口径

**触发：** 在侧栏或完整地图读到“声音与硬件 · 13 分钟”等值。节点只显示时长，可见图例主要解释箭头、次数、位置和大小；没有就近说明这些是分摊后的前台记录，也没有“前台时长不等于实际注意力”的可见文案。节点的 `aria-label` 有“分摊前台时长”，但普通视觉用户看不到。

**用户后果：** 官网明确强调“前台记录，不等于实际注意力”，访问路径也说明多主题分摊；进入真正名为注意力地图的核心页面后，这个边界反而不明显。用户容易把数字理解为在此主题上实际专注了多久，或误以为多主题各记全额。

**证据：** [侧栏完整下部](screenshots/panel-map-relation-bottom-360.png)，以及 `panel-map-360`、`workbench-map-handoff` 的全文；对照 [官网 320px](screenshots/site-mobile-map-320.png)、[访问路径](screenshots/map-relation-exact-path.png)。

**定位：** [app/app.js](../../../../app/app.js) L559–561、L642、L684–688；对照 L518–519 与 [website/index.html](../../../../website/index.html) L57。

**方向与验收：** 在地图图例就近补上“时长为分摊后的前台记录，不等于实际注意力”的简短说明，与官网/路径保持相同口径；无需新增专注分数、判断或惩罚表达。验证 320px 和完整页可读且不会盖住关系入口。此项本身不按 P2 阻塞处理，但属于概念一致性待修复项。

## 过审条件与未验证项

本次没有 P0/P1 的新 UI/UX 发现；**L-R1 至 L-R4 是需完成的 P2 条件，不应记为可选美化。** L-R5 可独立安排，但需要在概念一致性状态中继续标明待修复。未另列仅凭审美偏好提出的可选重设计，也不建议引入框架或增加动画来解决这些问题。

完成四项 P2 后，至少重走“写目标 → 保存后看见 → 设为当前聚焦 → 留断点 → 继续一页”和“地图键盘选关系 → 核对两端 → 返回 → 回到当前聚焦”，同时验证明确放弃与保留编辑两条退出路径，再给通过结论。

本次未验证屏幕阅读器实际朗读、触摸真机、原生工具栏关闭/重启后的状态、原生选项入口、真实浏览历史、商店审核或公网部署。现存后台检索/返回提示问题不在本报告中冒充已解决；UI/UX 通过也不能替代这些功能或发布验收。

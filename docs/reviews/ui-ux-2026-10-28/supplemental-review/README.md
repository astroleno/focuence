## Findings

### SR1 · P2：打开侧栏绕过弹窗的草稿保护

- **位置：** [popup/app.js:337](../../../../popup/app.js#L337)，按钮可用状态见同文件第 132 行。
- **复现：** 弹窗新建任务，填写名称和目标。按 Esc 会正常出现“继续编辑 / 放弃更改”，点击继续编辑后文字保留。随后点击顶部“打开侧栏”，立即离开编辑页，没有退出确认，侧栏也没有接收到该草稿。
- **实测：** 400×600 浏览器页面中，`侧栏交接草稿` 与目标文字在跳转前存在，跳转后的侧栏未显示；`guardPresent=false`。见[交接前](screenshots/SR1-popup-before-handoff.png)、[交接后](screenshots/SR1-panel-after-handoff.png)及 `SR1-popup-open-panel-discards-draft` 记录。
- **原因与影响：** 新的 `saveGuard` 只接入返回和 Esc；`open-panel` 独立调用 `openSidePanel()`。示例模式直接改变 `location.href`，真实扩展路径则在成功后主动 `window.close()`。这是产品提供的退出操作遗漏保护，不是前轮明确排除的“宿主强制销毁”。用户为了扩大编辑空间而进入侧栏，会丢掉尚未保存的目标和笔记。
- **建议验收：** 让该交接入口遵守同一草稿退出规则，或明确移交草稿；继续编辑必须保留输入，明确放弃后才离开。保存进行中也应控制该入口，避免提前关闭。需保留原生 `sidePanel.open` 的用户手势要求，不可简单在异步保存后自动调用而不验证。

### SR3 · P2：迟到的导航刷新覆盖用户新的滚动位置

- **位置：** [app/app.js:815](../../../../app/app.js#L815)，尤其第 816 行的第二次 `resetViewScroll()`。
- **复现：** 从地图进入当前聚焦，界面立即呈现已有任务；让本次 `GET_STATE` 暂时未返回，在等待期间向下滚动阅读任务。随后返回这次正常读取结果。
- **实测：** 完整页 `scrollY` 从 **627.5 → 0**；320×760 侧栏 `#main.scrollTop` 从 **620 → 0**。用户没有再次导航。见[响应前的阅读位置](screenshots/SR3-navigation-user-scroll-before-response.png)、[响应后回到顶部](screenshots/SR3-navigation-user-scroll-reset.png)，以及两条 `SR3-late-navigation-*` 记录。
- **原因与影响：** `navigationSerial` 只能判断是否再次切换视图，不能判断用户是否已在当前视图开始滚动。读取完成后仍无条件回顶，导致用户正在核对的任务或继续入口离开视线。这是 RR4 新增回顶逻辑的回归；本次用可控的待返回 Promise 复现，未把人工延迟说成真实后台性能测量。
- **建议验收：** 导航初次进入仍回顶；后续结果只在用户尚未改变阅读位置时维持初始落点。覆盖完整页与侧栏的“未操作”和“已滚动”两种分支，并保持地图关系返回时的精确定位。

### SR2 · P3：默认“日常任务”空态仍把归档过滤误写成首次使用

- **位置：** [src/task-memory-ui.js:404](../../../../src/task-memory-ui.js#L404)，第 407 行 `taskFilterEmpty()` 未处理 `daily`。
- **复现：** 在完整页通过三张任务卡的真实状态下拉框，把全部任务改为已归档；保持默认“日常任务”筛选。
- **实测：** 导航仍显示 **3** 个任务，列表显示 **0** 个；空态却写“先给眼前的事一个目标”，只提供“新建任务”，没有“查看全部任务”。手动改为全部任务后，三张归档卡均出现。见[空态截图](screenshots/SR2-daily-filter-all-archived.png)和 `SR2-daily-filter-empty-misclassified`。
- **原因与影响：** `daily` 会过滤归档任务，却不属于 `TASK_STATUSES` 的键，故空态 helper 返回 null，调用方退回真正空库的引导。没有删除数据，但与 RR2 的筛选空态解释要求及“从上次继续”的预期不一致。共享 helper 使同一逻辑也用于 popup；本次实际归档复现发生在完整页。
- **建议验收：** 区分“任务库真的为空”和“任务全部被日常筛选隐藏”，后者说明归档过滤并提供查看全部入口；首次使用空库继续保留新建引导。

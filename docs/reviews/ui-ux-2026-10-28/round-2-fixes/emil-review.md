## 注意力地图与聚焦主线

从交互证据看，当前主线有一致的对象和动作：地图回答“先访问什么、接着访问什么”，聚焦回答“这个窗口现在推进哪件事”，断点保留用户确认的下一步与继续页面，主要动作是“继续一页”。主题、任务、浏览器分组以及记录开关仍有清楚边界。

地图选中“视觉创作 → 声音与硬件”后，路径同时列出 09:42–09:45 的摄影页面与 09:45–09:49 的 ESP32 页面，保留先后角色、时刻和返回所选关系动作。这里没有以主题筛选代替同一次切换的证据，也没有随意用另一条同 URL 访问补位。见 [两端证据截图](screenshots/map-exact-two-endpoints.png) 和 `map-exact-two-endpoints`、`RR3-map-return-keeps-relation`。

目标保存后未自动成为当前聚焦，之后的显式选择、确认下一步和继续页、单页继续均有本轮证据。最终当前区把目标、确认断点、继续页放在同一阅读序列内，批量恢复留在任务列表的次要位置。见 [目标→断点→继续一页](screenshots/focus-flow-goal-checkpoint-continue-one.png)。暂停此窗口的聚焦也没有被混写成暂停浏览记录。

官网源码和构建未在本轮改动；320px 地图补图中的主题、次数、单位和说明可读，没有横向溢出。官网演示的“注意力地图 / 当前聚焦 / 断点继续”与扩展三端的角色对应成立。此处只复核一致性及已有窄屏修复的回归，不代表重新验收官网全部流程或已更新线上版本。

## 证据中的中间失败与边界

[browser-checks.json](browser-checks.json) 在本报告复核时有 64 条观察，其中 63 条为 true。唯一 false 为 `RR3-range-removal-has-honest-fallback`：工具只改了范围值，没有把焦点先移到范围控件，却断言控件应已获焦。该记录的 main 回退与缺失说明符合源码逻辑；最终 `RR3-range-user-control-focus-final` 先聚焦再操作，控件焦点与说明均成立。因此它不是一项悬而未决的产品缺陷。

初始 RR2 三次创建曾因冻结 `Date.now()` 得到相同 demo ID，不能用于证明创建三个对象。最终按真实经过时间递增的时钟复测产生三个不同 ID，并分别在对应筛选下验证；本报告采用最终记录，不用初始成功标记代替复验。

本轮对失败保存的验证来自受控 demo transport 夹具，证明界面保留草稿、说明生效状态与提供重试；没有证明真实磁盘故障恢复。原生 popup 被浏览器销毁后的草稿持久性、真实扩展宿主生命周期、屏幕阅读器完整路径、触摸真机、真实权限/模型及既有后台缺陷未在本轮重测，不能据此宣称通过。本结论仅关闭此次六项 UI/UX 修复及直接相关回归。

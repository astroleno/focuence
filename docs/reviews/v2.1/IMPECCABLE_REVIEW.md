# Focuence V2.1 独立 Impeccable UI/UX 评审

本轮采用 **Operate** 标准：人在浏览中整理页面、留住下一步、恢复任务，界面应帮助他们迅速识别对象和完成动作。本报告先独立查看截图并记录设计判断，再核对源码，最后运行一次辅助 detector；没有阅读旧 V2 评审或另一位 reviewer 的结论，没有修改实现。

## 整体 Verdict

**需要重新组织界面和视觉语言，不能按“再调一点间距就好”验收。** 三层产品职责成立；主要问题在于，同一种宽松的绿色卡片布局被套到弹窗、窄侧栏和完整回顾上，界面框架与说明占据了太多先手位置，真正要继续的任务、保存完成动作和地图证据却来得偏晚。

这套 UI 有一致性，也具备可识别的控件。它的不足不是没有设计，而是设计优先级偏向“所有区域都温和、完整、整齐”，没有充分表现浏览器工具需要的精确、快速和对象辨识。用户所说的“丑”，有可定位的结构原因：灰绿底、浅绿控件、绿字、绿图、白色圆角块反复出现，形成一层厚而均匀的视觉包裹；内容之间的主次不够有力。

**anti-pattern / slop 结论：存在明显的模板化产品 UI 倾向。** 最典型的是卡片套子覆盖多种内容、用低差异绿灰色组织全部状态、把四个统计和一幅大柱图当成回顾的默认主角，以及用圆点连线的外形承担尚未解释清楚的关系。系统字体、低彩度和标准按钮本身适合 Operate；问题是它们没有被编排成适合这三个容器的工作界面。

## 已经做对的部分

1. **三层职责适合使用场景。** 弹窗负责短动作；侧栏持续陪伴；完整页承接七天回顾、完整地图和数据管理。打开侧栏、打开完整页和展开地图的入口已经存在，下一轮应在此架构上设计。
2. **任务保存了“回来做什么”的对象信息。** 名称、下一步备注、上次页面和“复用 / 新开”预估，比只有收藏夹标题更能帮助恢复上下文。见 [最近任务截图](./before/popup-native-recent-task.png) 与 [app/app.js:264](../../../app/app.js)。
3. **状态与控制有实际基础。** 分组前可勾选成员、可撤销最近分组；删除有确认；恢复失败有提示；路径区分前台、暂离和缺口；完整地图提供关系表和访问例证。它们为重设计提供了可复用的行为，而不是需要凭空扩功能。

## 五个优先问题

### 1. [P1] 窄容器先展示框架，持续任务被推到后面

**截图事实：** [侧栏任务](./before/panel-native-tasks.png) 先经过品牌、状态、当前页面、四项导航、标题与说明、保存窗口、搜索和任务数，第一张任务卡约在 y=419 才出现。[320 侧栏示例](./before/panel-320-demo.png) 还包含示例提示，第一项任务约到 y=494 才开始，所给画面尚未出现它的“继续任务”。示例横幅确实增加高度，但真实插件图也存在同方向问题。

**代码事实：** 外壳明确分成四层：[app/app.js:136](../../../app/app.js)–143；任务标题、说明、保存动作和搜索再被排到列表之前：[app/app.js:281](../../../app/app.js)–291。侧栏主要采用字号/间距覆盖和单列化，仍沿用完整页的页头结构：[app/styles.css:295](../../../app/styles.css)–319。

**影响判断：** 用户打开一个持续工作的窄栏，却需要先扫描一组产品介绍式区域，才能找回上一件事。它并不是信息量太多，而是高价值信息获得的空间太晚。路径页也显示同一种失衡：顶部很松，记录中的标题和“10 分钟”却紧贴在一起，见 [侧栏路径](./before/panel-native-path.png)；对应窄栏标题行 `display:block`、时长 `inline-block`，并没有形成稳定的标题/元信息列：[app/styles.css:320](../../../app/styles.css)–325。

**下一轮设计：** 把品牌、记录状态和常用工具压为一行；四个导航保留一行；当前页面信息只在与当前操作相关的位置出现。任务视图用一行“任务 / 保存窗口”工具栏和紧凑搜索，直接进入任务对象。任务列表以名称、下一步、继续动作构成第一阅读层，上次页面和时间属于第二层。设计验证应检查 320 与 360 宽的真实侧栏，在常见高度下首项任务的恢复动作是否直接可见，而不仅检查有没有横向溢出。

建议使用 `shape / layout / distill`，先改结构再改视觉细节。

### 2. [P1] 地图看起来像关系图，但图形规则和操作证据不够自解释

**截图事实：** [真实侧栏地图](./before/panel-native-map.png) 中，四个绿色大圆和方向箭头占据核心区域；其中 `Blen…` 被截断，次数没有直接标在连线上，选中详情位于图下。[完整地图示例](./before/full-map-demo.png) 有更完整的标签与侧边详情，但圆形轨道、中央大节点和粗箭头仍强烈主导阅读。

**代码事实：** 主题按时长排序；第一项放中心且采用固定较大半径，其余等角分布在圆周，位置不表示语义距离，圆面积也不是严格的时长比例：[app/app.js:408](../../../app/app.js)–430。窄栏只显示前五个主题，标签按字符数截断：[app/app.js:418](../../../app/app.js)、[app/app.js:469](../../../app/app.js)。完整页的“节点是主题，箭头是访问先后”说明在侧栏被隐藏：[app/app.js:510](../../../app/app.js)、[app/styles.css:327](../../../app/styles.css)。次数与实例要选中连线后到详情阅读：[app/app.js:476](../../../app/app.js)–493。

**影响判断：** 图形容易让人推断“中心更重要”“邻近更相关”“大圆按时长成比例”，但实现只为排布方便采用这些位置和尺寸。这是解释成本，不是已经证实的用户误读。真正有用的事实是“从哪个主题接着去了哪里、几次、发生在哪个页面”，当前却被放在图的后面。窄栏用户尤其难以把一个被截断的圆点和下方证据连接起来。

**下一轮设计：** 保留轻量地图，改成围绕所选主题的局部访问关系，明确声明“访问先后”；用完整文字标签、可读的方向与次数，让图本身先回答一个问题。紧接着展示选中主题和前几条访问关系，再提供“展开完整地图”。完整图保留关系表和访问实例，并为节点尺寸、位置、线宽各自给出唯一且真实的规则；没有数据含义的尺寸差异应取消。不要把这轮修复扩成知识图谱或新的语义聚类系统。

建议使用 `shape / clarify / layout`。

### 3. [P2] 绿灰容器的权重过于平均，视觉上缺乏“工作对象”和“界面工具”的区别

**截图事实：** [弹窗分组](./before/popup-native-groups.png)、[侧栏任务](./before/panel-native-tasks.png)、[完整回顾](./before/weekly-native-desktop.png) 共同采用浅绿底、白色圆角卡、浅绿控件、绿色次级字和深绿动作。分区存在，但很多不同行为被同类填色和圆角赋予相近视觉分量。任务里的“上次停在”又形成一层浅绿容器，进一步加厚卡片感。

**代码事实：** 全局颜色集中在相邻绿灰色，主半径 10px：[app/styles.css:3](../../../app/styles.css)–10；任务卡/上次页面分别填色：[app/styles.css:148](../../../app/styles.css)–156；统计、柱图、主题卡再次容器化：[app/styles.css:276](../../../app/styles.css)–289；弹窗也采用同样卡片语法：[popup/styles.css:17](../../../popup/styles.css)–38。

**影响判断：** 界面显得温和、均匀，却不够精确。任务、控件、状态、统计和图形都被染成一种产品情绪，削弱了扫读和物体辨识。仅增大字号或再加留白会让这种观感更明显。

**下一轮设计：** 采用中性工作台底色与较深正文；把填色保留给选中、主要动作和重要状态，用行、细分隔和对齐组织列表。任务作为清晰的内容对象，工具栏作为安静的界面工具；不再给每段上下文都加一块背景。保留现有名称与图标，允许重新选择主色；深绿可保留为少量强调，也可在完整设计稿中验证更适合工具感的墨蓝。此处是方向建议，尚非新的品牌批准。

建议使用 `shape / colorize / typeset`，不建议直接对现有卡片做 `polish`。

### 4. [P2] 七天回顾先报告数量，再提供可以继续的内容，文案也错配了图表的问题

**截图事实：** [完整回顾](./before/weekly-native-desktop.png) 中，四个总量和宽大的逐日柱图占据主要上半屏；主题与任务从下方才开始。在 [窄屏回顾](./before/weekly-narrow-demo.png) 中，六个导航入口、顶栏、示例说明、页头和统计继续纵向堆叠，图表到 y≈664 才开始。窄屏图是示例，不能据此推断真实首屏一定同高；但源代码确认了相同的纵向顺序。

**代码事实：** 回顾固定按“标题 → 四统计 → 日柱图 → 主题/任务”输出：[app/app.js:298](../../../app/app.js)–325。图标题是“这七天，停留在哪里”，横轴实际是日期；这回答的是“每天停留多久”，不是“停留在哪里”。`反复回到的主题` 同样使用时长排名，标题没有准确说明排序依据：[app/app.js:319](../../../app/app.js)–321、[app/app.js:371](../../../app/app.js)–375。

**影响判断：** 回顾看起来先是一张普通统计仪表盘，再附带任务。现有数据本来可以帮助用户看清主题与继续入口，但图表面积和阅读顺序没有服务这一目的。“前台”“分摊”“未知”等口径需要准确解释；把事实口径集中放在长页面末尾，也增加了理解成本。

**下一轮设计：** 四统计收为紧凑摘要；主题分布与已有任务并置，先呈现能辨识的对象；逐日时长图作为次一级趋势区域。标题直接写“每天的前台停留”“按前台时长排列的主题”，并把必要口径放在对应图表附近。使用现有数据和模块即可，不需要新增 AI 周报、专注力评分或生产力结论。

建议使用 `layout / clarify / distill`。

### 5. [P2] 弹窗保存页的完成动作缺乏稳定位置

**截图事实：** [保存截图](./before/popup-native-save.png) 能看到任务名、下一步备注、两项页面选择，但所给画面没有呈现“保存任务”。它证明这一帧的动作不可见，不证明按钮不存在或保存不能完成。

**代码事实：** 提交按钮确实在选择列表之后：[popup/app.js:74](../../../popup/app.js)–87。主区可滚动，页面选择列表又有独立滚动：[popup/styles.css:16](../../../popup/styles.css)、[popup/styles.css:56](../../../popup/styles.css)。两层滚动和按内容排布的提交动作，会让有限高度下的完成位置不稳定。这是源码支持的布局风险，尚未测完键盘/窗口高度组合。

**下一轮设计：** 保存页使用直白的“保存任务”标题；备注标为可选；名称、备注和页面选择留在一个明确的内容滚动区，取消与提交留在表单自己的稳定底部。显示已选页数和 30 页上限，把错误留在对应选择区。“返回”与“取消”的语义在设计中统一：这里是放弃当前保存，不是打开另一个产品层级。

建议使用 `layout / clarify / adapt`。

### 认知负担与典型使用者

- **急着回来继续的人：** 最近任务卡中的“下一步、上次页面、复用/新开”是正确线索；侧栏却先展示保存窗口和多层框架。应把寻找已存任务与创建新任务的权重按当前视图分清。
- **第一次使用的人：** 能理解“整理页面 / 最近任务 / 应用分组”；地图中的圆、尺寸、方向与被截断主题需要试点才能理解。抽象的“思路之间的接续”“留住这件事”适合辅助语气，主标题和提交动作应使用明确对象名。
- **依赖键盘或辅助技术的人：** 原生按钮/复选框、表单标签、`aria-live`、SVG 按钮标签和 Enter/Space 处理都有源码基础，不能说它完全不支持键盘。导航按钮有稳定的 `id: 'nav-' + view`，`render()` 也尝试按 id 恢复焦点，见 [app/app.js:161](../../../app/app.js)、[app/app.js:550](../../../app/app.js)–574；本轮没有现场验证导航切换后的键盘或读屏体验，不据此断言存在焦点丢失。地图关系表在侧栏不提供，SVG 的可操作体验也需实测。未测对比度、200% 缩放或屏幕阅读器，不宣称符合无障碍标准。

从截图看，没有一个主要决策点必须先读十几个同级选项；问题更接近“信息顺序和容器开销”，不宜机械地把所有六项导航都删掉。情绪曲线的低点是“想马上继续，却先处理界面”和“看见地图，却仍不确定它说明什么”；保存成功、恢复完成的反馈是现有的正向结束节点。

## 推荐的 Operate 视觉方向

**方向：浏览器里的资料工作台。** 中性浅底、白色内容面、石墨正文和一个受控强调色，靠对齐、分隔和对象名称建立秩序。名称与图标形成辨识，使用中的内容形成性格。绿灰无需成为整面的固定滤镜。

- 内容区优先采用清单/行；只为真正独立的编辑区域或摘要保留容器。圆角服务控件边界，不成为所有区域的共同装饰。
- 使用一套系统无衬线字；窄栏正文 13–14px、对象名 15–17px 即可形成紧凑层级。用粗细、位置和行关系拉开主次，减少“每页再来一个大标题”。这是设计起点，最终以真实窄栏可读性校正。
- 一个视图只保留一个最明确的主要动作，其余使用安静的按钮/文字层级。深色动作与当前选中状态应易于区分。
- 地图中颜色、节点大小和线宽均要有说明得通的任务含义。纯排布产生的强调要撤掉；不靠动画掩盖解释困难。

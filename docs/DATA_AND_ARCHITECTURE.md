# Focuence 2.0：数据与实现说明

版本：2.1.0

更新日期：2026 年 10 月 22 日

本版把快速分组、任务恢复和浏览回顾放在浏览器本机执行。生成式云端请求已从运行链路中移除；本地模型负责计算页面向量，分组名称、访问时长和路径统计由确定性代码处理。本文说明交付版本已经实现的行为，不把待开发能力写成现成功能。

## 1. 三类对象，各自负责什么

| 对象 | 含义 | 关键区别 |
|---|---|---|
| 页面 `Page` | 清洗网址对应的资源 | 页面 ID 是清洗网址的稳定哈希；同一网址可以被多次访问 |
| 访问片段 `Segment` | 某个页面在某个连续观察时段中的状态 | 保存当时的标题、标签、起止时间和状态，避免后来导航或改标签覆盖过去身份 |
| 任务 `Task` | 用户主动保存的页面集合与备注 | 最多保存 30 个页面，保留到用户删除，不由相似度判断“已经完成” |

浏览器的 tab ID 只用于当前会话内定位标签页；它不是永久页面 ID。语义标签 `tags` 描述主题，原生浏览器分组用于整理当前窗口，保存的任务则用于日后恢复资料，三者分开存储。

## 2. 模块与调用路径

| 模块 | 当前职责 |
|---|---|
| [`background.js`](../background.js) | 接收界面消息、读取浏览器状态、串行提交活动记录、调用本地推理、应用和撤销分组、保存及恢复任务 |
| [`src/text.js`](../src/text.js) | 清洗网址和标题、生成页面 ID、提供规则标签和模型短文本输入 |
| [`src/grouping.js`](../src/grouping.js) | 生成规则／语义分组建议；保护已识别的项目边界，不直接改浏览器 tab |
| [`src/activity.js`](../src/activity.js) | 纯函数访问片段状态机，处理焦点、导航、空闲、暂停、重启与缺测 |
| [`src/store.js`](../src/store.js) | IndexedDB 读写、原子保存、保留期清理、导出与清除 |
| [`src/analytics.js`](../src/analytics.js) | 今日统计、主标签有向转移、低样本回退与轻量建议 |
| [`inference/worker.js`](../inference/worker.js) | 本地 BGE 向量推理，使用随包提供的 ONNX／WASM 文件 |
| `app/`、`panel/`、`popup/` | 完整回顾页、原生侧栏和短操作弹窗，共享后台消息与同一份本机数据 |
| [`src/tasks.js`](../src/tasks.js) | 去重恢复计划、继续页面、复用/新开预览及最近任务排序 |
| [`src/ui.js`](../src/ui.js)、[`src/navigation.js`](../src/navigation.js) | 共享渲染和三层入口导航；侧栏在用户点击内直接调用原生 API |

界面通过 `chrome.runtime.sendMessage({target:'background', type, ...payload})` 调用后台，结果统一为 `{ok:true,data}` 或 `{ok:false,error}`。读取当前浏览器上下文的函数本身不写历史；实际记录走活动队列，再由 `saveActivity` 在同一数据库事务中保存状态和片段。

`GET_STATE` 会先在队列中对当前状态做一次核对，再读取统计。用于显示的临时片段预览不修改传入状态，并按 segment ID 覆盖已有快照；不会把预览当成一次新访问重复累计。

2.1 的 `GET_STATE {windowId, range}` 支持 `today / yesterday / week`，返回 `attention {range, summary, nodes, daily}`。后台以完整选定范围计算节点、边和概况；最新 2,000 条限制只作用于列表。七天以本地日历计算，使用日期加减而不是固定 24 小时，覆盖夏令时边界。侧栏地图仅预览主要五个主题；完整地图和关系表包含全部主题与关系。

任务保存兼容新增 `lastRestoredAt`、`lastActivePageId` 和 `lastRestoreResult {at, opened, reused, failedCount}`，数据库结构版本不变。恢复根据当前窗口的真实网址计算缺页，复用已打开页面；逐页失败不阻止其余页面恢复。结果先持久化再激活页面，使弹窗关闭后仍保留失败提示。继续页优先为任务中当前活动页面，其次为近七天内最近访问页，再退回已记住的恢复页或首个保存页。

各入口与验收边界详见 [V2_EXTENSION_SURFACES.md](V2_EXTENSION_SURFACES.md)。

## 3. 本地分组：规则先可用，模型按需增强

### 输入范围

本版读取 Chrome 标签页 API 提供的标题和网址等元数据。规则标签来自标题、域名、网址路径和预设关键词；它们不是模型对网页正文的概括。

模型输入由标题、域名与清洗网址中的可读路径／应用路由组成。当前页面读取链路不抓取正文，也不执行页面内脚本。普通查询参数可能保留在页面身份中，但不会整段拼入当前模型输入。

网址清洗会：

- 去除 URL 中的用户名、密码和规则列出的认证／追踪参数。
- 保留用于区分内容的查询参数，并稳定排序。
- 合并普通文档锚点，保留 `#/…` 或 `#!/…` 形式的应用路由。
- 只接受 HTTP(S) 页面，并排除无痕和用户设置的域名。

清洗不是匿名化。保留的网址路径、标题和有意义的查询仍可能包含用户信息；临时签名链接或某些被删除参数也可能影响后续恢复，网站需要登录时仍由网站处理。

### 两条分组路径

**快速整理**使用确定性规则：重复页面、同一仓库／设计文件／文档、高区分度主题词和标题词相近性。它可以在模型未加载时运行。

**本地语义增强**使用 BGE-small-zh-v1.5 q8 计算向量，再以相似度补充分组。当前配置为本地 WASM、单线程推理、CLS pooling、归一化的 512 维向量；tokenizer 的截断上限为 128 tokens。输入长度受限，因此长标题和信息不足的标题可能降低分组质量。

向量缓存按页面 ID 保存，并同时校验模型标识和输入文本哈希。未改变的页面可以复用向量；新增或文本发生变化的页面才重新计算。这个机制减少重复推理，但不代表已经完成实时常驻的全量增量分类。

分组采用保守的成员匹配：加入组的页面需要与组内其他成员都满足规则或语义条件，避免相似链条不断吞入不相关页面。已有建议会用于保持名称和成员稳定；用户固定的 tab 和已经属于原生组的 tab 不作为新分组候选。组名从项目身份或共同主题词生成，不需要第二次生成式模型调用。

### 应用与撤销

建议只针对选定的一个普通浏览器窗口，点击应用才创建原生组。应用前再次检查页面仍存在、尚未分组、未固定、处于同一窗口且网址未发生不匹配的变化，不会先清除其他窗口的分组。

撤销仅针对本浏览器会话中最近一次 Focuence 分组。后台会核对组名、颜色、页面顺序及组成员状态；用户已经手动修改窗口时会拒绝撤销，以免覆盖后续操作。撤销信息和建议保存在会话存储中，普通 worker 回收后仍可恢复；真实浏览器会话结束后不作为长期历史保存。

### 模型加载和回收

模型与运行文件随完整安装包提供，推理配置关闭远程模型加载，扩展页面的连接策略限制为自身来源。后台在 offscreen 页面中运行专用 worker，共享一个模型会话。

最近一次推理或预热请求会刷新五分钟的模型回收闹钟。闹钟触发后关闭 offscreen 页面，下一次需要语义增强时从本地重新加载；向量缓存继续保留。实际回收时刻受浏览器闹钟调度影响。本文不承诺冷启动、内存或端到端响应时间，具体数值应以交付验收与目标设备实测为准。

## 4. 时间线记录什么

默认设置为 `tracking:true`、`semantic:true`、`idleSeconds:120`、`retentionDays:30`。无痕页面始终排除，站点排除同时匹配域名和子域名。

只有一个符合条件的前台页面能占用当前访问片段。后台结合活动标签、浏览器窗口焦点及系统空闲状态记录，不能仅凭某个 tab 的 `active` 属性累加时长。

| 状态 | 当前解释 | 是否计入前台时长 |
|---|---|---|
| `active` | 观察到符合条件的前台页面，且系统状态为 active | 是 |
| `idle` | 当前页面仍可定位，但系统报告 idle 或 locked | 否 |
| `unknown` | 已存证据与新观察之间出现无法安全连续计算的间隔 | 否 |

失去浏览器焦点、进入不可记录页面或暂停时，会关闭当前片段。暂停不删除已存内容，也不阻止用户手动执行分组和任务操作。

### 关键边界

1. **同 tab 导航**：页面 ID 或网址改变时结束上一片段，为新页面开启新片段；不把一整个 tab 生命周期的时长都算给最后一个 URL。
2. **心跳**：后台设置约 30 秒的观察闹钟。同一片段的确认快照使用同一 ID 更新，不增加访问次数。闹钟可被浏览器延后，不能把它当精确秒表。
3. **长缺测**：默认连续性上限为 90 秒。两次确认相隔超过该值时，整个未确认间隔记为 `unknown`，不把缺测时间归到最后一页。
4. **浏览器重启**：会话存储中的标识用于区分真实重启与普通 worker 唤醒。重启保留已确认数据，缺口单独标记；没有新上下文时不自动重开旧页面。
5. **时钟倒退**：停止累加并暴露时钟异常状态，直到时间重新达到先前确认点，避免负时长和重复统计。
6. **后台回收**：记录状态和访问片段在同一 IndexedDB 事务中保存，worker 重新启动后从持久状态恢复。

这里的“前台时长”是可解释的浏览器状态统计。没有键鼠动作时，用户仍可能正在阅读；窗口有焦点时，用户也可能在看其他地方。数据不用于断言专注程度、心理状态或某项工作已经完成。

## 5. 今日统计、关系地图与建议

### 今日统计

“今日”采用设备的本地日历边界，跨午夜片段会按边界裁剪。前台总时长只计算 `active` 部分；重复快照按 ID 合并，对异常重叠的前台片段也会防御性去重。

同一访问片段有多个标签时，时长在标签之间平均分摊。因此各标签时长相加不会把同一分钟重复计为多分钟。“今日页面数”来自有前台时长证据的页面，扫描到一个仍打开的 tab 不会自动增加此数。

### 有向关系

关系边使用访问片段的第一个标签作为主标签，表示观察到的页面切换方向。当前标签主要来自规则识别，地图不等同于 embedding 的相似度空间，也不表达因果关系。

- 转移计算使用至少持续一秒的前台访问，不把快速掠过的零时长快照当作完整转移证据。
- 不跨越 idle、unknown、失焦、暂停或重启边界拼接相邻转移。
- 跨主题边记录次数、独立工作时段数、平均间隔和最近观察时间。
- 概率分母包含同主题的页面切换，图中只隐藏自环。因此可见出边的概率之和可以小于 100%。

这是对观察到的路径做统计，并不表示浏览器捕获了用户全部工作活动。

### 轻量建议

下一主题建议至少需要同一方向在 **三个独立工作时段**中被观察到，且累计不少于三次。不同浏览器会话、至少十五分钟的间隔或相应长时间非活跃区间可形成新的工作时段；短时间内反复切换不会被当成三次独立验证。

达到门槛后，系统按转移记录为当前上下文提供相关页面入口，并说明观察次数和时段数。内部 `confidence` 是带平滑的排序辅助值，不是经过校准的正确率，也不代表对用户意图的判断。建议不自动打开网页。

样本不足时显示最近在前台访问过的页面或已保存任务资源，明确标为回顾／恢复入口，`confidence` 为 `null`。记录暂停、系统空闲或有时钟异常时，不生成“当前主题下一步”的预测。普通页面上下文缺失时不推测当前主题；用户在 Focuence 工作台回顾时，后台可使用十五分钟内最近的已记录前台片段作为回顾上下文。

## 6. 数据落在哪里

IndexedDB 数据库名称为 `focuence-local-v2`，当前数据库结构版本为 1，导出格式版本为 `schemaVersion:2`。二者是不同的版本号。

| Store | 保存的主要内容 | 保留方式 |
|---|---|---|
| `meta` | settings、当前访问状态、会话标识与最后确认时间 | 设置持续保留；活动状态随观察更新，清理会处理过期片段起点 |
| `pages` | 稳定 ID、清洗网址、标题、域名、标签、最近观察时间 | 过期且不再被保留片段或任务引用时清理 |
| `segments` | 访问时的页面快照、时间、active/idle/unknown、结束原因、tab/window/session 标识 | 按设置的历史保留期清理和裁剪 |
| `tasks` | 名称、颜色、备注、页面列表、创建及修改时间 | 手动保存后不自动过期 |
| `vectors` | 页面向量、模型标识、文本哈希、更新时间 | 根据更新时间清理；清除历史或全部数据时删除 |

`chrome.storage.session` 保存浏览器会话 ID、撤销信息及当前窗口建议。它服务于会话内恢复，不参与长期统计导出。运行期间的模型内存不属于 IndexedDB。

记录中的起止时间、观察时间和更新时间为毫秒时间戳；导出的 `exportedAt` 是 ISO 8601 时间字符串。页面和片段里的哈希 ID 是稳定定位符，不能视为去标识化；模型向量也应按用户数据缓存对待。

## 7. 保留期、清除和导出

设置页提供 7、30、90、365 天；后台校验范围为 1 至 365 天。修改设置时执行清理，之后通过每小时闹钟再清理，设备休眠或浏览器关闭可能延后执行。

清理会删除已结束且过期的片段，裁剪横跨截止时间的片段，并把同步裁剪后的活动状态回填到后台内存，避免下一次心跳把旧起点写回来。仍由保存任务引用的页面可以保留；任务本身不会因浏览历史过期而消失。

| 控制 | 历史与页面索引 | 向量缓存 | 已保存任务 | 设置与后续记录 |
|---|---|---|---|---|
| 暂停记录 | 已有内容保留，不新增访问片段 | 保留，手动语义操作仍可使用 | 保留 | 记录关闭，其他设置保留 |
| 增加排除站点 | 阻止后续记录，不追溯删除已有内容 | 旧缓存按保留期处理 | 已保存任务保留 | 新候选和新任务保存也应用排除规则 |
| 清除历史 | 删除本版历史、页面索引和当前片段状态 | 删除 | 保留 | 保留设置，若仍开启记录则后续重新记录 |
| 清除全部 | 删除 | 删除 | 删除 | 恢复默认设置，默认记录开启 |

两种清除都会清空会话内的分组建议和撤销信息，不会关闭浏览器已经打开的页面。

导出为未加密 JSON，含 `schemaVersion`、`exportedAt`、`pages`、`tasks`、`segments`、`settings`。不导出模型权重、向量缓存、当前 open 状态、撤销信息或临时分组建议。导出文件可能包含完整的清洗网址、页面标题和用户备注；它保存在用户下载位置，扩展内删除不会处理这些文件。

工作台读取近七天的记录用于概况和关系计算，时间线界面最多展示最近 2,000 条并提示截断。完整导出包含数据库中仍保留的全部片段，不受界面条数限制；若保留期较短，界面也只能显示尚未被清理的数据。

## 8. 任务恢复与联网边界

保存任务会留下页面清单和备注。恢复时在目标普通窗口中复用清洗后网址相同的页面，缺少的页面在后台打开；每个任务上限为 30 个页面。恢复不会重建网页表单、滚动位置、原生组布局或网站登录状态。

扩展分析只使用本地文件与本地数据。打开或恢复在线网页后，浏览器及网页本身仍会正常联网，网站自己的数据处理不由这个扩展接管。开发者从源码构建时下载公开依赖和模型文件，也不同于运行期间上传浏览记录。

## 9. 当前交付边界

当前没有 JSON 导入、跨设备同步、云备份、应用层加密、系统级跨应用监测或自动恢复全部工作现场。语义相似和访问次序都不能直接证明两个页面属于同一个实际任务，任务保存仍由用户确认。

本版不读取或迁移 1.x 的旧存储：旧版字段含义、计时方式和注意力指标与本版不兼容，不能直接写入新的片段表。若覆盖安装保留了旧 `chrome.storage.local` 数据，本版不会使用它；本版清除功能也不等同于完成旧版格式迁移或清理旧版 API 配置。旧数据需用旧版工具或浏览器数据管理另行处理。

`?demo=1` 是独立的界面示例入口，必须显示示例标识；它不接入生产记录链路，不应把示例数据写入实际数据库。生产空状态直接显示尚无记录，不补随机注意力分数。

隐私与用户控制的简版说明见 [`PRIVACY.md`](../PRIVACY.md)。关键边界的自动化验证位于 [`test/activity.test.js`](../test/activity.test.js) 和 [`test/activity-analytics.test.js`](../test/activity-analytics.test.js)；真实浏览器中的分组、后台恢复与模型行为应结合交付验收结果判断。

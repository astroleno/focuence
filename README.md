## 三个入口

| 入口 | 日常操作 |
| --- | --- |
| 工具栏弹窗 | 生成规则建议、勾选分组成员、直接应用与撤销；保存当前窗口或一组页面；预览复用/新开页数并恢复最近任务 |
| 原生侧栏 | 网页旁持续管理任务与下一步备注；随当前页面切换更新；查看访问路径和主要主题的轻量地图 |
| 完整页 | 最近七个本地日历日的回顾、全部主题地图与关系表、具体切换证据、JSON 导出、设置及数据清理 |

弹窗的短操作直接完成。需要持续管理时点“打开侧栏”；需要深入回顾时再进入完整页。恢复会复用当前窗口中已打开的页面，只新开缺失页面。部分失败会留下提示，重试不会重复打开已恢复的页面。每个任务最多保存 30 页。

“保存窗口”始终取当前窗口，“保存所选”只取显式勾选；保存框内可以调整成员，同一地址只保留一份。长备注默认展示最多三行摘要，继续任务在摘要之前，展开后保留全文及换行。编辑时取消删除会回到原草稿。

已固定和已经分组的标签页受到保护。GitHub 与 GitLab 多层子组的项目边界分别识别；应用前仍可移除不合适的建议成员。

## 响应与本地模型

规则建议先返回，不等待模型。按需使用弹窗下方的本机模型入口，由随包提供的 **BGE-small-zh-v1.5 q8** 在本机计算 512 维向量，补充保守的语义聚合。相同网址和文本输入复用持久缓存，模型闲置约五分钟后释放。

输入为标题、域名和清洗网址中的路径信息，不抓取网页全文；组名由确定性规则生成。中文短文本优先，跨语言、短标题和大批量页面的质量仍需要实际体验。初次加载和缓存命中的耗时不同，本版不承诺固定秒数。模型处理时仍可在弹窗保存窗口、查看和继续最近任务，或打开侧栏继续浏览；不可用时明确回退到规则建议。

## 路径、地图与一周回顾

前台停留来自浏览器窗口焦点、活动页面与设备 idle 状态，**不等于实际注意力，也不判断工作是否完成**。失焦、暂停、暂离、重启或缺少连续观察的间隔不会包装成专注时长。

地图的节点表示主题，箭头表示已经观察到的主主题先后关系；不表示语义相似或因果关系。多 tag 的时长平均分摊。侧栏点选次数按钮、完整页点选次数或连线，可以查看对应页面与时刻；点选主题可以回到访问路径。

今天、昨天和近七天由后台统一裁剪与聚合。地图、关系表、时间线概况使用所选范围内的完整记录；列表只展示最新 2,000 条，不影响统计。侧栏以所选主题及其直接前后主题组成局部图，次数可以查看访问例证。完整图保留全部主题，左右列明确表示先访问与接着访问；默认聚焦选中主题的直接关联，可切换全部连线，完整关系表始终保留。主题尺寸不编码时长，位置不表示语义距离。

日期切换期间显示加载，成功后一起更新日期和记录；失败保留原日期与数据，并可重试。侧栏展开完整地图会保留日期、所选主题及关系；有未展开的局部关系或已失效的对象时明确说明。

一周回顾显示连续七天、逐日前台时长、访问页数、切换次数及主题分布。新安装从真实记录开始；没有记录的日期显示零。继续线索只在证据足够时提供下一主题候选，否则优先找回最近页面或保存任务。

2026-10-22，在 macOS arm64 的隔离 **Chrome for Testing 156.0.8078.47** 中实际加载 MV3 扩展，使用本轮创建的合成网页验证；没有读取日常浏览器资料。

- **61 项逻辑测试通过，构建通过**：在原有 54 项基础上增加保存地址去重、长备注与 emoji 摘要、局部图隐藏数量、地图上下文及原生页复用接口的回归。
- **15 组界面与交互检查通过，保留 29 张截图**：覆盖 400×520/600 弹窗、320×720 / 360×765 侧栏、1280×900 完整地图；检查长备注、31→30 页纠错、取消删除保留草稿和光标、键盘筛选、日期失败与乱序、地图交接及模型等待期间保存。
- **本轮原生扩展验证**：真实弹窗应用/撤销分组、保存 4 页任务、打开原生侧栏、单页复用、恢复缺失页面和重复恢复均通过。界面边界测试使用生产 UI 与内存 demo 传输，原生流程另用真实 Chrome API 验证，两者不混算。
- **定向补验通过**：日期失败、乱序响应，以及改变主题后重新打开旧地图上下文；最后一项防止复用完整页时丢失定位。未再进行一轮视觉改版。

本机模型、部分失败重试、导出文件、周回顾、4/8/20 主题压力布局和代表性对比度的既有证据见 [2.1 历史验证](docs/reviews/v2.1/README.md)，不作为本轮重测结果。2.1.1 未修改推理管线，也未重新测量模型耗时。

这是开发体验版。Windows、Edge、长期真实浏览、大批量页面的分类质量及峰值内存尚未逐项实测。原附件曾记载的 Linux 小样本性能属于历史资料，不作为本机承诺；现有检查也不是全站读屏认证。

## 从源码重建

需要 Node.js 22+、npm、Python 3.10+。首次构建需要下载固定依赖与公开模型，构建后的分析在本机运行。

```bash
npm ci --ignore-scripts
python3 scripts/download-model.py
npm run build
npm test
```

`package-lock.json` 锁定依赖；`model-lock.json` 锁定模型 revision、大小和 SHA-256。源码包不重复包含模型、生成的 worker 或 WASM；离线包包含全部运行资产。

需要另行制作离线包时运行 `npm run package`，`dist/` 会生成离线 ZIP、源码 ZIP、安装说明和校验文件。每个 ZIP 含内部文件校验清单和 `build-info.json`；其中 `sourceDirty` 标识是否包含未提交修改，`sourceTreeSha256` 标识该次实际源码快照，不能只靠 HEAD 提交号推断安装包内容。

开发时可直接加载仓库目录；修改推理 worker 后先重新构建，再在扩展管理页重新加载。

## 数据与后续边界

默认记录开启，暂离阈值 120 秒，历史保留 30 天。任务不随历史自动删除。暂停、站点排除、保留期、模型开关、导出及清理都在完整页“数据与设置”，弹窗与侧栏也可暂停记录。

所有记录、任务、恢复结果和向量缓存保留在当前浏览器。没有账号、遥测或云推理。主动打开/恢复网页时，网页本身仍正常联网。JSON 导出是明文，包含标题、网址和任务备注。

2.1 继续使用 2.0 的本地数据库，兼容原任务；不把 1.x 的旧注意力字段转换成有效时长。历史 PRD / PROGRESS 属于旧设计，当前运行行为以本 README 与 `docs/` 为准。

自定义 tag、按任务过滤历史、JSON 导入、跨设备同步、全文检索和生成式总结尚未实现，属于后续独立设计。优先用日常浏览验证分组接受率、任务恢复操作数和从回顾找回页面的速度，再决定预测应扩展到什么程度。

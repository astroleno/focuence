# Focuence 智序 · 本机版 2.0

一个可以直接加载到 Chrome / Edge 的浏览器扩展：快速整理标签页，把相关资料保存为任务，并从真实的访问顺序与前台停留时间回顾工作路径。

本版本基于 [astroleno/focuence](https://github.com/astroleno/focuence) 的 `240eaba9c1b5517b0c3fc96973c195b44042ef32` 重构，采用已交付的 2.0.0 源码包作为 **V2 开发基线**。本轮已复核 41 项逻辑测试、本地构建及示例界面；原包记录的扩展端到端验证单独列在下文。

这不是正式发布候选：已发现界面残留文字、GitLab 嵌套项目识别和大量记录下的地图统计口径问题。包来源与纳入范围见 [V2_BASELINE.md](docs/V2_BASELINE.md)，缺口、截图和 UI/UX 建议见 [V2_REVIEW.md](docs/V2_REVIEW.md)。新增功能和界面改版仍是待确认建议。

## 直接安装

使用随本次交付提供的 **Focuence-2.0.0-offline.zip**，先解压，再打开 `chrome://extensions`（Edge 为 `edge://extensions`），启用开发者模式，点击“加载已解压的扩展程序”，选择里面含有 `manifest.json` 的 `Focuence-2.0.0` 文件夹。

完整安装步骤、首次体验路线、升级与故障处理见 [INSTALL.md](INSTALL.md)。安装包内已有模型、推理库和 WASM；**使用安装包不需要 Node、Python、API Key 或模型下载**。

## 本版可以做什么

| 页面 | 可用功能 |
| --- | --- |
| 扩展弹窗 | 看当前窗口页面、今日前台时长，暂停记录，快速整理，进入工作台 |
| 当前页面 | 搜索/筛选/选择页面；快速规则建议；手动运行本机语义增强；确认后应用；撤销最近一次分组 |
| 任务工作台 | 保存页面集合、改名、编辑继续工作的备注、删除任务；恢复时复用已经打开的页面 |
| 时间线 | 按今天/昨天/近七天回看页面访问；区分前台、暂离与未知；按主题筛选 |
| 注意力地图 | 显示主题间已经观察到的有向切换、主题分摊时长、关系明细；点击主题回到时间线 |
| 继续的线索 | 优先提供最近访问和保存的任务；证据足够时提供带次数与时段依据的下一主题候选 |
| 设置 | 暂停、站点排除、暂离阈值、保留期、模型开关、JSON 导出、清历史或清全部 |

固定的标签页和现有浏览器分组受到保护。已有测试覆盖 GitHub 不同仓库的项目边界；GitLab 多层子组的识别存在已知缺陷，修复前请逐组确认建议。单个任务最多保存/恢复 30 页。

### 为什么响应会更轻

快速分组不等待模型：标题关键词、明确主题、项目身份等规则直接返回候选。需要进一步归类时，使用打包在扩展中的 **BGE-small-zh-v1.5 q8**，在本机把标题和清洗后的网址信息变成 512 维向量，再作保守的语义聚合。这里没有串行的云端生成请求。

模型按需加载。相同页面与相同文本输入的向量持久化缓存，标题/网址变化后重新计算，模型闲置约 5 分钟后释放。初次分析和全部命中缓存的成本不同；低性能设备或大量页面仍可能较慢，快速规则始终可用。

本版使用标题、域名和路径，没有抓取网页全文。模型中文优先，跨语言和短标题的语义判断仍需要人工确认。组名来自确定性的主题/标题规则，未另加生成式模型。

### 注意力地图表达什么

“前台停留”来自浏览器焦点与设备 idle 状态，**不等于实际注意力，也不判断事情是否完成**。同一时刻只记录一个合格网页；失焦、暂离、暂停、重启以及长时间未确认的缺口不会被包装成专注时长。

地图的节点是主题，箭头是已经观察到的访问先后；箭头不表示内容相似度或因果关系。多 tag 页面的时长分摊，避免重复累计。跨暂离/未知的访问不拼接成关系。

下一主题候选至少需要在三个独立工作时段观察到对应转移，且显示支持次数；样本不足时只是最近访问/任务恢复入口。新安装的地图从空白开始。

## 从源码重建

需要 Node.js 22+、npm、Python 3.10+。首次构建需要联网取得公开依赖和固定版本模型；构建后的扩展运行不需要联网分析。

```bash
npm ci --ignore-scripts
python3 scripts/download-model.py
npm run build
npm test
npm run package
```

`--ignore-scripts` 避免安装本扩展不使用的 Node/CUDA 运行时下载脚本；浏览器只使用打包的 WASM。`package-lock.json` 锁定 npm 依赖，`model-lock.json` 锁定模型 revision、每个文件大小与 SHA-256。下载脚本会校验完整性。

`dist/` 生成完整离线安装 ZIP、源码 ZIP 和校验文件。源码包不重复附上模型与生成的 WASM，可按以上命令重建。

开发时可将仓库目录直接“加载已解压的扩展程序”；修改源文件后执行构建（推理 worker 改动时）并在扩展管理页点击重新加载。

## 数据与限制

- 默认记录开启，暂离阈值 120 秒，历史保留 30 天；手动任务不会随历史自动删除。
- 记录、任务、向量缓存仅在本机。没有账号、遥测、云推理或同步。
- URL 会清除已知追踪/凭证参数，但保留对页面身份有意义的查询。JSON 导出是明文，可能包含个人页面标题、路径和任务备注。
- 当前 UI 展示近 7 天最新 2,000 条访问片段；统计使用近 7 天全量记录，完整保留期内的记录可导出。
- 本版没有 JSON 导入、跨设备同步、全文语义检索或自动生成长篇总结。
- 旧版注意力字段和记录方式不一致，未自动转换成 2.0 的有效时长。新版本从新的本地数据表开始。
- 本版本替换了后台与主界面；仓库中历史 PRD / PROGRESS 等旧文档属于 1.0 设计，当前运行行为以本 README、INSTALL 和 `docs/` 为准。

详细数据结构与算法见 [docs/DATA_AND_ARCHITECTURE.md](docs/DATA_AND_ARCHITECTURE.md)，隐私说明见 [PRIVACY.md](PRIVACY.md)。第三方模型/推理库的来源和许可见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

## 下一轮最值得验证的事

先用真实日常浏览积累一周，观察：分组建议实际接受率、从任务卡恢复上下文是否节省操作、时间线是否能帮助找回“刚才在做什么”。在这三件事得到反馈后，再决定是否加入自定义 tag、跨语言模型、正文摘要或更复杂的预测。这样可以保持第一次整理快、任务恢复直接可用。
